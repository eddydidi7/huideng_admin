## 1. 数据和接口

复用现有 app_notices / app_links，新增字段而不是重建；现有计数表只读统计。
新增 admin_private.members、audit_logs、requests，分别为管理员权限、不可通过客户端修改的审计日志、重复请求凭据。客户端无访问私有表和管理 RPC 的权限。
唯一公开管理入口是 Edge Function admin-api。它验证登录令牌，使用验证得到的 user ID 调用服务端管理 RPC。RPC 再查角色、启用状态，每个动作单独授权。身份或角色不能由请求参数伪造。
service_role 仅从 Edge Function 环境读取；不进入 Flutter、配置 JSON 或安装程序。Flutter 只使用项目 URL、公开 key 和登录会话；会话仅在内存，退出/重开不复用用户端登录。

## 2. 测试部署顺序（不要直接对生产执行）

1. 准备独立 Supabase 测试项目；已有用户端结构对应的 001_counter_sync、003_app_links、004_app_notices 迁移需先应用。002_home_messages 不依赖。
2. 审阅并应用本工程 supabase/migrations/202609150005_admin_phase1.sql。
3. 部署 supabase/functions/admin-api，保留 JWT 校验，并验证普通账号返回拒绝。
4. 项目所有者创建并确认专用管理员邮箱账号。将 bootstrap_super_admin.sql 的占位邮箱替换为该账号后执行一次。不要把已有普通用户自动提升权限。
5. 开启 Supabase Cron，确认没有同名任务后执行 enable_schedule.sql。定时任务每分钟检查一次，到期后发布；可有约一分钟和客户端缓存周期的延迟。未配置 Cron 前不能宣称定时发布已经可用。
6. 本地 build-config.json 只填写 ADMIN_SUPABASE_URL 和 ADMIN_SUPABASE_PUBLIC_KEY。不得填写 service_role、数据库密码、存储密钥。
7. 首位管理员验证通过后，可在“系统设置 → 后台管理员”邀请已注册账号的权限。super_admin 全权限，admin 本期通知和首页，moderator 只开放尚未接入的论坛入口。

## 3. Windows 构建

安装 Visual Studio 的“使用 C++ 的桌面开发”，包含 MSVC、Windows SDK、CMake。Windows 插件需要可创建符号链接的环境，系统开发者模式由电脑所有者自行设置。

```powershell
flutter doctor -v
flutter pub get
flutter analyze
flutter test
flutter build windows --release --dart-define-from-file=build-config.json
```

预期输出 build/windows/x64/runner/Release/huideng_admin.exe（以实际编译结果为准）。分发整个 Release 文件夹，不可只复制 EXE。
installer/huideng_admin.iss 为 Inno Setup 模板，需安装带 ChineseSimplified.isl 的官方 Inno Setup 中文语言文件后用 ISCC 编译。当前未验证安装包，未签名；正式分发应安排代码签名。

## 4. 验收要求

- 普通用户拒绝后台登录和每个管理接口；不能绕过界面调管理 RPC。
- 版主不能发通知、读取用户统计或授权管理员。
- 管理员不能授权自己或提升他人角色；超级管理员不能在此降级自己。
- 同一写请求 UUID 重复发送只执行一次，不同内容复用 UUID 拒绝。
- 相同版本被两人修改，后保存的请求收到冲突，不覆盖前者。
- 草稿/定时未到/软删除不出现在旧版用户端；定时任务重复执行不重复发布。
- 角色撤销后下一次接口调用立即拒绝，即使旧 token 还存在。
- CSV 统计、图片上传、文章和论坛等后续功能不得伪造为已完成。

## 5. 当前统计口径

北京时间每日边界，今日计数活跃=当日存在计数变化记录的用户，不等于所有打开 APP 的用户。计数为已同步事件 delta 的净和，包含人工校正；离线未上传数据不在统计内。数值以字符串返回避免大整数精度损失。
